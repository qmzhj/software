# 个人设置功能需求规格说明

## 3.2.6 个人设置

### 3.2.6.1 功能概述

允许已登录用户在个人设置页面查看个人基本信息（角色、姓名、学号/工号），并修改手机号、登录密码和个人简介。所有可修改字段均为可选更新，用户可选择修改其中任意字段的组合。修改操作需要用户二次确认。

---

### 3.2.6.2 前置条件

1. 用户已完成登录，`localStorage` 中存在有效的 `token`、`uid`、`name`、`role`、`phone`。
2. 页面加载时自动从 `GET /api/userinfo` 获取当前用户的 `description`（个人简介）。
3. 浏览器已加载 `profile.html`。

---

### 3.2.6.3 查看基本信息

#### 3.2.6.3.1 输入与输出

**API 接口：** `GET /api/userinfo`
- 认证要求：需要有效的 Bearer Token
- 成功响应（`200 OK`）：

```json
{
  "uid": "202421326577",
  "name": "曹云龙",
  "role": "student",
  "phone": "13800138000",
  "description": "Hello World"
}
```

#### 3.2.6.3.2 显示规则

| 字段 | 数据来源 | 前端显示规则 |
|------|----------|-------------|
| 角色 | `localStorage.getItem("role")` | 英文映射为中文：`"student"` → `"学生"`，其他值（`"teacher"`、`"manager"` 等）→ `"教师"`。输入框 `disabled` |
| 姓名 | `localStorage.getItem("name")` | 直接显示。输入框 `disabled` |
| 学号/工号 | `localStorage.getItem("uid")` | 直接显示。输入框 `disabled` |
| 手机号 | `localStorage.getItem("phone")` | 预填至输入框。输入框可用，允许修改 |
| 个人简介 | `GET /api/userinfo` 的 `description` | 页面加载后通过 fetch 获取，回填至文本域 |

**不可修改字段的视觉特征：** 输入框采用 `disabled` 属性，背景色变为灰色（`#e2e8f0`），文字颜色变为灰暗色（`#64748b`），鼠标指针变为 `not-allowed`。

---

### 3.2.6.4 修改信息

#### 3.2.6.4.1 输入输出规范

**API 接口：** `PUT /api/userinfo`
- 认证要求：需要有效的 Bearer Token
- 请求 Content-Type：`application/json`

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `phone` | 字符串 | 否 | 新手机号，完整提交时才更新；为空字符串时不更新 |
| `password` | 字符串 | 否 | 新密码，有值时更新；为空字符串时不更新 |
| `description` | 字符串 | 是 | 个人简介内容。**始终提交**，允许空字符串（用于清空简介）。最大长度 200 字符 |

**请求示例（仅修改简介）：**
```json
{"description": "计算机学院2024级学生"}
```

**请求示例（修改手机号和密码）：**
```json
{"phone": "13912345678", "password": "NewAbc12345", "description": ""}
```

**成功响应：** `200 OK`，`{"message": "修改成功"}`

**失败响应：** `400 Bad Request`，`500 Internal Server Error`

#### 3.2.6.4.2 修改流程

##### 步骤 1 — 用户输入

用户在修改信息区域编辑以下字段：

| 字段 | HTML ID | 输入类型 | 约束 |
|------|---------|----------|------|
| 手机号 | `phoneInput` | `tel`，`maxlength="11"` | 可选。提交时若不为空则需满足手机号格式 |
| 新密码 | `pwdInput` | `password` | 可选。提交时若不为空则需满足密码复杂度规则 |
| 确认新密码 | `confirmPwdInput` | `password` | 当新密码不为空时必填，必须与新密码一致 |
| 个人简介 | `descInput` | `textarea`，`maxlength="200"` | 始终提交，允许空字符串。宽度自适应，最小高度 80px |

##### 步骤 2 — 前端验证

用户点击"保存修改"按钮后，前端执行以下验证（按顺序）：

| 顺序 | 验证项 | 验证逻辑 | 失败处理 |
|------|--------|----------|----------|
| 2.1 | 修改内容非空检查 | 检查 `phone`、`password`+`confirmPwd`、`description` 中至少有一项相对于原值发生了变更 | 错误提示区显示"修改内容为空"，终止流程 |
| 2.2 | 手机号格式验证 | 若 `phone` 非空，使用正则 `/^1[3-9]\d{9}$/` 校验 | 错误提示区显示"请输入有效的手机号"，终止流程 |
| 2.3 | 密码长度验证 | 若 `pwd` 非空，检查长度 `>= 8` | 错误提示区显示"密码至少需要8位"，终止流程 |
| 2.4 | 密码复杂度验证 | 若 `pwd` 非空，使用正则 `/(?=.*[a-z])(?=.*[A-Z])(?=.*\d)/` 校验 | 错误提示区显示"密码必须包含大小写字母和数字"，终止流程 |
| 2.5 | 密码一致性验证 | 若 `pwd` 非空，检查 `pwd === confirmPwd` | 错误提示区显示"两次输入的密码不一致"，终止流程 |

##### 步骤 3 — 用户二次确认

前端弹出浏览器原生确认对话框（`confirm()`），显示文字"是否确认修改个人信息？"。

- 用户点击"取消"：终止流程，不发送请求。
- 用户点击"确定"：继续执行步骤 4。

##### 步骤 4 — 构建请求数据

前端构建 JSON 请求体：

```javascript
const requestData = {};
if (phone) requestData.phone = phone;         // 手机号非空时才包含
if (pwd) requestData.password = pwd;           // 密码非空时才包含
requestData.description = descInput.value;     // 始终包含简介（可能为空字符串）
```

##### 步骤 5 — 发送请求

前端通过 `fetch` 向 `PUT /api/userinfo` 发送 JSON 请求，携带 `Authorization` 请求头。

##### 步骤 6 — 后端验证与处理

| 顺序 | 处理项 | 逻辑 |
|------|--------|------|
| 6.1 | 密码格式验证 | 若请求包含 `password` 且非空，使用正则 `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$` 校验。失败返回 `400 {"error": "密码需包含大小写字母和数字，至少8位"}` |
| 6.2 | 密码更新 | 若 `password` 非空，计算 `SHA-256(password + "CampusFakeSalt2024!")`，执行 `UPDATE users SET password=<哈希值> WHERE uid=<当前用户>` |
| 6.3 | 手机号更新 | 若 `phone` 非空，执行 `UPDATE users SET phone=<新手机号> WHERE uid=<当前用户>` |
| 6.4 | 简介更新 | 若 `description` 不为 `None`（即请求中包含了该字段），执行 `UPDATE users SET description=<简介内容> WHERE uid=<当前用户>`。空字符串用于清空简介 |
| 6.5 | 提交事务 | 执行 `conn.commit()` |
| 6.6 | 返回成功 | 返回 `200 {"message": "修改成功"}` |

##### 步骤 7 — 前端处理结果

**成功：**
1. 若修改了手机号，更新 `localStorage.setItem("phone", 新手机号)` 并刷新页面中的手机号输入框值。
2. 清空密码输入框和确认密码输入框的值。
3. 成功提示区显示"修改成功！"，3 秒后自动清除。
4. 错误提示区清空。

**失败：**
1. 错误提示区显示后端返回的 `error` 信息或"修改失败，请重试"。
2. 成功提示区清空。

#### 3.2.6.4.3 密码复杂度规则

| 规则项 | 正则/条件 | 说明 |
|--------|----------|------|
| 最小长度 | `.{8,}` | 总长度至少 8 个字符 |
| 小写字母 | `(?=.*[a-z])` | 至少包含 1 个小写英文字母 |
| 大写字母 | `(?=.*[A-Z])` | 至少包含 1 个大写英文字母 |
| 数字 | `(?=.*\d)` | 至少包含 1 个数字 |

前端验证正则：`/(?=.*[a-z])(?=.*[A-Z])(?=.*\d)/`（仅校验包含关系，不校验长度——长度校验单独进行）

后端验证正则：`^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$`（完整校验）

#### 3.2.6.4.4 手机号格式规则

前端验证正则：`/^1[3-9]\d{9}$/`
- 以 `1` 开头
- 第二位为 `3`-`9`
- 后跟 9 位数字
- 总长度 11 位

---

### 3.2.6.5 异常/备选流程

| 异常场景 | 检测时机 | HTTP 状态码 | 返回/提示信息 |
|----------|----------|-------------|--------------|
| 所有修改字段均为空或与原值相同 | 前端步骤 2.1 | N/A | `修改内容为空` |
| 手机号格式不正确 | 前端步骤 2.2 | N/A | `请输入有效的手机号` |
| 密码长度不足 8 位 | 前端步骤 2.3 | N/A | `密码至少需要8位` |
| 密码缺少大小写字母或数字 | 前端步骤 2.4 | N/A | `密码必须包含大小写字母和数字` |
| 两次密码不一致 | 前端步骤 2.5 | N/A | `两次输入的密码不一致` |
| 用户取消确认 | 前端步骤 3 | N/A | 不发送请求，无提示 |
| 密码格式不符合规则 | 后端步骤 6.1 | 400 | `密码需包含大小写字母和数字，至少8位` |
| Token 无效 | 后端 Token 验证 | 401 | `登录已过期` |
| 数据库更新异常 | 后端步骤 6.5 | 500 | `系统繁忙` |
| 网络错误 | 前端 fetch | N/A | `修改失败，请重试` |

---

### 3.2.6.6 键盘支持

- 页面支持回车键提交：在任意输入框中按下回车键（`keypress` 事件，`event.key === 'Enter'`）触发 `saveProfile()` 函数。

---

### 3.2.6.7 数据完整性约束

| 约束项 | 规则 |
|--------|------|
| 密码存储 | 数据库中仅存储 SHA-256 哈希值，不存储明文密码 |
| 简介长度 | 最大 200 字符（前端 `maxlength` 属性限制，后端无长度校验） |
| 手机号唯一性 | 当前版本无手机号唯一性约束，多个用户可以绑定相同手机号 |
| 字段独立性 | 三个可修改字段（手机号、密码、简介）彼此独立，未填写的字段不会被更新 |
| 本地存储同步 | 手机号修改成功后同步更新 `localStorage`，用户名和角色不在个人设置页面修改 |

---

### 3.2.6.8 后置条件

1. 密码修改成功：用户在下一次登录时必须使用新密码。
2. 手机号修改成功：忘记密码流程中将使用新手机号接收验证码。
3. 简介修改成功：其他用户在群组成员信息弹窗中可查看到更新后的简介内容。
4. 页面刷新后，所有已保存的修改仍然生效（已持久化到数据库）。
