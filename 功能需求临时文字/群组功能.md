# 群组与消息功能需求规格说明

## 3.2.5 群组与消息功能

### 3.2.5.1 功能概述

本功能涵盖群组容器管理、聊天室管理、私聊消息收发、群聊消息收发、消息撤回、成员信息交互、用户简介、好友管理、黑名单管理九个子功能。系统采用两级群组架构：**群组容器（user_groups）** 作为组织单元，包含成员和聊天室；**聊天室（groups_chat）** 作为实际的多人聊天空间。私聊消息通过独立的消息表（`messages`）实现一对一通信。

系统通过前端轮询（2 秒间隔）实现消息实时性，不依赖 WebSocket。

**远期规划（待实现）：** 与学校官方数据源（学生录取名单、课程选课结果、校园活动报名表）对接，实现群组的自动创建与成员自动同步（详见 3.2.5.11）。

---

### 3.2.5.2 前置条件

1. 用户已完成注册并登录，`localStorage` 中存在有效的 `token`。
2. 数据库已初始化，`users`、`messages`、`groups_chat`、`group_members`、`group_messages`、`user_groups`、`user_group_members`、`user_group_chats`、`friends`、`blacklist` 表已创建。
3. 登录时已调用 `ensure_default_groups(uid)`，确保用户拥有"即时聊天"、"私聊"两个系统群组。

---

### 3.2.5.3 群组容器管理

群组容器（`user_groups` 表）是一个组织单元，用于将成员和聊天室组织在一起。系统群组（`group_type = 'system'`）由系统自动创建，自定义群组（`group_type = 'custom'`）由用户手动创建。

#### 3.2.5.3.1 创建群组

**API 接口：** `POST /api/user-groups`

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | 字符串 | 是 | 群组名称，1-50 字符 |
| `category` | 字符串 | 否 | 分类，默认 `"自定义"`，可选值：自定义、课程、比赛、班级、年级、学院、办公 |
| `members` | 字符串数组 | 否 | 初始成员学号/工号列表 |
| `chats` | 对象数组 | 否 | 初始关联聊天室列表，每项包含 `chat_id` 和 `chat_name` |

**创建流程：**
1. 前端检测 `name` 非空，若为空则提示"请输入群组名称"，终止流程。
2. 前端弹出创建群组弹窗（`createGroupModal`），显示所有系统用户供选择（复选框）和所有已有聊天室供关联（复选框）。
3. 前端发送 POST 请求，携带名称、分类、成员列表、聊天室列表。
4. 后端生成 `group_id = secrets.token_hex(8)`（16 字符随机十六进制字符串）。
5. 后端在 `user_groups` 表插入记录，`creator` 为当前用户，`group_type = 'custom'`，`created_at = time.time()`。
6. 后端将创建者加入 `user_group_members` 表。
7. 后端遍历 `members`，对每个在 `users` 表存在的成员插入 `user_group_members`。
8. 后端遍历 `chats`，将每个聊天室关联到群组（插入 `user_group_chats`）。
9. 返回 `201 {"message": "群组创建成功", "group_id": group_id}`。

#### 3.2.5.3.2 查看群组列表

**API 接口：** `GET /api/user-groups`

返回当前用户所属的所有群组容器列表，每项包含：`group_id`、`name`、`creator`、`created_at`、`group_type`、`category`、`chat_count`、`member_count_except_self`。

**动态计数规则：**

| 群组类型 | 成员数计算方式 | 聊天室数计算方式 |
|----------|---------------|-----------------|
| 系统群组 - 即时聊天 | 所有用户数 - 好友数 - 自己 | N/A |
| 系统群组 - 私聊 | 好友数 | N/A |
| 系统群组 - 课程（学生） | N/A | 学生选修的课程数（`lesson_stu` 表） |
| 系统群组 - 课程（教师） | N/A | 教师教授的课程数（`lesson` 表） |
| 自定义群组 | `user_group_members` 表统计（排除自己） | `user_group_chats` 表统计 |

#### 3.2.5.3.3 查看群组详情

**API 接口：** `GET /api/user-groups/<group_id>/detail`

返回群组的成员列表和关联聊天室列表。访问者必须在群组中，否则返回 403。

**成员列表来源：**

| 群组类型 | 成员来源 |
|----------|---------|
| 系统群组 - 即时聊天 | 所有非好友用户（排除自己） |
| 系统群组 - 私聊 | 好友列表（`friends` 表） |
| 自定义群组 | `user_group_members` 表 |

#### 3.2.5.3.4 添加群组成员

**API 接口：** `POST /api/user-groups/<group_id>/members`
- 输入：`{"uids": ["<学号>", ...]}`
- 仅自定义群组可添加成员（系统群组返回 403）。
- 自动跳过不存在的用户和已在群组中的用户。
- 返回添加的成员数量。

#### 3.2.5.3.5 移出群组成员

**API 接口：** `DELETE /api/user-groups/<group_id>/members/<member_uid>`
- 仅自定义群组可移出成员（系统群组返回 403）。
- 不能将自己移出群组（返回 400）。

#### 3.2.5.3.6 删除群组

**API 接口：** `DELETE /api/user-groups/<group_id>`
- 仅创建者可删除群组。
- 级联删除 `user_groups`、`user_group_members`、`user_group_chats` 中的相关记录。
- 不删除关联的聊天室本身（仅解除关联）。

#### 3.2.5.3.7 修改群组

**API 接口：** `PUT /api/user-groups/<group_id>`
- 仅创建者可修改群组。
- 可修改字段：`name`、`category`。

### 3.2.5.4 聊天室管理

聊天室（`groups_chat` 表）是实际的多人聊天空间，可关联到群组容器。每个聊天室设有角色体系：

| 角色 | 权限 |
|------|------|
| `admin`（群主） | 全部权限：踢出、设管理员/取消管理员、重命名、发布公告 |
| `manager`（管理员） | 重命名、发布公告 |
| `member`（普通成员） | 发送/读取消息、邀请成员 |

#### 3.2.5.4.1 创建聊天室

**API 接口：** `POST /api/groups`

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | 字符串 | 是 | 聊天室名称，1-50 字符 |
| `members` | 字符串数组 | 是 | 初始成员学号/工号列表，至少 1 个 |
| `category` | 字符串 | 否 | 分类，默认 `"办公群"` |

**创建流程：**
1. 前端验证 `name` 非空、`members` 非空。
2. 后端验证所有成员在 `users` 表中存在。
3. 生成 `group_id = secrets.token_hex(8)`。
4. 插入 `groups_chat` 表（`creator` = 当前用户，`group_type = 'custom'`）。
5. 创建者以 `admin` 角色加入 `group_members`。
6. 其他成员以 `member` 角色加入 `group_members`。
7. 插入系统消息 `{"sender":"system","content":"聊天室已创建"}`。
8. 返回 `201 {"message": "群聊创建成功", "group_id": group_id}`。

#### 3.2.5.4.2 在群组内创建聊天室

**API 接口：** `POST /api/user-groups/<group_id>/create-chat`

在指定群组容器内创建聊天室并自动关联：
1. 创建聊天室（同 3.2.5.4.1 流程）。
2. 可额外指定 `members` 作为初始成员（范围为平台所有用户，通过弹窗复选框勾选）。
3. 将聊天室自动关联到指定群组容器（插入 `user_group_chats`）。
4. 插入系统消息：`"{创建者姓名} 创建了聊天室"`。

#### 3.2.5.4.3 关联已有聊天室到群组

**API 接口：** `POST /api/user-groups/<group_id>/chats`
- 将已有聊天室关联到群组容器。
- 系统群组不可修改（返回 403）。

**API 接口：** `DELETE /api/user-groups/<group_id>/chats/<chat_id>`
- 解除聊天室与群组的关联。

#### 3.2.5.4.4 查看聊天室详情

**API 接口：** `GET /api/groups/<group_id>/detail`

返回聊天室的完整信息，包括：
- 基本信息：`group_id`、`name`、`creator`、`group_type`
- 成员列表：每项含 `uid`、`name`、`role`（admin/manager/member）、`joined_at`

#### 3.2.5.4.5 前端聊天室详情界面

用户在聊天室界面时，右上角显示"⋯ 详情"按钮。点击后弹出聊天室详情弹窗（`chatDetailModal`），包含以下功能：

| 界面元素 | 功能 | 权限限制 |
|----------|------|----------|
| 聊天室名称 + 群主标记（🔑） | 显示 | 全部成员可见 |
| 管理员标记（🛡️） | 显示 | 全部成员可见 |
| "✏️ 重命名"按钮 | 编辑聊天室名称 | 仅群主/管理员 |
| "📢 公告"按钮 | 发布公告弹窗 | 仅群主/管理员 |
| 成员列表（头像、姓名、角色标签） | 点击触发成员信息弹窗 | 全部成员 |
| "踢出"操作 | 移出成员 | 仅群主（不可踢出群主和自己） |
| "设为管理"/"取消管理"操作 | 管理管理员权限 | 仅群主 |
| "邀请成员"按钮 | 弹窗选择用户加入 | 全部成员 |
| "退出聊天室"按钮（红色边框） | 退出确认对话框 | 全部成员 |

#### 3.2.5.4.6 邀请成员

**API 接口：** `POST /api/groups/<group_id>/invite`
- 当前用户必须在聊天室中。
- 邀请范围为平台所有用户（`users` 表中不在当前聊天室的用户）。
- 邀请不存在的用户会被跳过，已在聊天室的用户会被跳过。
- 成功后插入系统消息：`"{邀请者姓名} 邀请了 N 位成员"`。

#### 3.2.5.4.7 踢出成员

**API 接口：** `POST /api/groups/<group_id>/kick`
- 仅群主（`admin` 角色）可踢出成员。
- 不能踢出自己，不能踢出群主。
- 被踢出用户的**所有消息**从 `group_messages` 表中删除。
- 插入系统消息：`"{被踢用户姓名} 已被移出聊天室"`。

#### 3.2.5.4.8 管理员管理

**API 接口：** `POST /api/groups/<group_id>/admin`
- 仅群主（`admin` 角色）可管理管理员。
- `action = 'set'`：将目标成员角色设为 `manager`。
- `action = 'unset'`：将目标成员角色恢复为 `member`。
- 不能修改群主权限。

#### 3.2.5.4.9 聊天室重命名

**API 接口：** `PUT /api/groups/<group_id>/rename`
- 仅群主和管理员（`admin`、`manager` 角色）可重命名。
- 名称不能为空。

#### 3.2.5.4.10 发布公告

**API 接口：** `POST /api/groups/<group_id>/announcement`
- 仅群主和管理员（`admin`、`manager` 角色）可发布公告。
- 公告内容不能为空。
- 公告以系统消息形式插入：`"📢 公告 - {发布者姓名}: {公告内容}"`。

#### 3.2.5.4.11 退出聊天室

**API 接口：** `POST /api/groups/<group_id>/leave`
- 若退出者是群主且聊天室还有其他成员，禁止退出（返回 `{"error": "群主不能退出，请转让群主"}`）。
- 若退出者是群主且聊天室仅剩自己，允许退出（聊天室自动解散）。
- 退出后插入系统消息：`"{用户姓名} 退出了聊天室"`。

### 3.2.5.5 私聊消息

私聊消息通过 `messages` 表存储，实现一对一通信。

#### 3.2.5.5.1 发送私聊消息

**API 接口：** `POST /api/send`

支持文本消息和文件消息两种方式。

**文本消息（Content-Type: application/json）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `receiver` | 字符串 | 是 | 接收者学号/工号 |
| `content` | 字符串 | 是 | 消息文本内容 |
| `msg_type` | 字符串 | 否 | 消息类型，默认 `"text"` |

**文件消息（Content-Type: multipart/form-data）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `receiver` | 字符串 | 是 | 接收者学号/工号 |
| `msg_type` | 字符串 | 是 | 可选值：`image`、`video`、`audio`、`file` |
| `content` | 字符串 | 否 | 可选的文字描述 |
| `file` | File | 是 | 上传文件 |

**文件上传规则：**
- 文件名格式：`{时间戳}_{原始文件名}`，通过 `secure_filename` 清理。
- 文件存储路径：`static/uploads/`。
- 全局上传大小限制：`500MB`（Flask 配置 `MAX_CONTENT_LENGTH`）。

**发送流程：**
1. 前端获取输入内容，若为空字符串则终止。
2. 前端通过 `fetch` 发送 POST 请求到 `/api/send`。
3. 后端检查接收者非空，若为空返回 `400`。
4. 后端生成时间戳 `time.time()`，插入 `messages` 表。
5. 返回 `201 {"message": "发送成功", "timestamp": <时间戳>}`。

#### 3.2.5.5.2 获取私聊消息

**API 接口：** `GET /api/messages?with=<对方学号>`

- 返回当前用户与指定用户之间的全部消息（按时间升序排序）。
- 自动将对方发来且未读的消息标记为 `status = 'read'`。

**消息字段说明：**

| 字段 | 说明 |
|------|------|
| `id` | 消息 ID（自增主键） |
| `sender` | 发送者学号 |
| `receiver` | 接收者学号 |
| `content` | 消息内容（文本消息为文字，文件消息可为空或描述） |
| `msg_type` | `text`、`image`、`video`、`audio`、`file`、`system` |
| `file_path` | 文件访问路径（文件消息） |
| `file_name` | 原始文件名（文件消息） |
| `file_size` | 文件大小（字节） |
| `status` | 消息状态：`sent`（已发送）、`read`（已读） |
| `timestamp` | 发送时间的 Unix 时间戳（秒） |
| `revoked` | 是否已撤回：`0`（否）、`1`（是） |

**渲染规则：**

| `msg_type` | 渲染方式 |
|------------|----------|
| `text` | 直接显示文本内容，HTML 转义 |
| `image` | 显示图片（`<img>`，最大 200px × 180px，圆角） |
| `file` | 显示文件链接（`📎 文件名`，可下载） |
| `system` | 居中灰色文字，无气泡样式 |
| `revoked=1` | 显示斜体灰色文字"已撤回" |

#### 3.2.5.5.3 撤回消息

**API 接口：** `POST /api/messages/revoke/<msg_id>`
- 仅消息发送者可撤回自己的消息。
- 撤回时限：消息发送后 **2 分钟内**（`time.time() - timestamp > 120` 禁止撤回）。
- 超过 2 分钟返回 `400 {"error": "超过2分钟无法撤回"}`。
- 撤回后 `messages.revoked` 置为 `1`，不删除消息记录，前端显示"已撤回"占位文本。

#### 3.2.5.5.4 前端私聊流程

1. 用户从群组详情页的成员列表中点击某个成员，触发 `startPrivateChat(uid, name)`。
2. 私聊界面右上角显示"⋯ 详情"按钮（点击后弹出成员信息弹窗）。
3. 前端发送 `GET /api/messages?with=<uid>` 加载聊天记录。
4. 启动 2 秒轮询定时器，持续调用 `loadPrivateMessages()` 获取新消息。
5. 用户在输入框输入文字，点击发送按钮（`send-btn`）或按回车键。
6. 前端调用 `POST /api/send` 发送消息，成功后清空输入框并刷新消息列表。
7. 黑名单过滤：若发送者或接收者在当前用户的拉黑列表中，该消息在前端被过滤不显示。
8. 切换到其他聊天（私聊或群聊）时，清除轮询定时器。

### 3.2.5.6 群聊消息

群聊消息通过 `group_messages` 表存储，实现多人聊天。

#### 3.2.5.6.1 发送群聊消息

**API 接口：** `POST /api/groups/<group_id>/send`
- 发送者必须在聊天室中（`group_members` 表存在记录），否则返回 403。
- 支持 JSON（文本）和 multipart/form-data（文件）两种方式，格式同私聊消息（3.2.5.5.1）。
- `sender` 为发送者学号。

#### 3.2.5.6.2 获取群聊消息

**API 接口：** `GET /api/groups/<group_id>/messages`
- 返回聊天室中的所有消息（按时间升序排序）。
- 每条消息通过 `LEFT JOIN users` 附带 `sender_name`（发送者姓名），系统消息（`sender='system'`）通过 `COALESCE` 显示为"系统"。
- 访问者必须在 `group_members` 中，否则返回 403。

#### 3.2.5.6.3 前端群聊流程

1. 用户在群组详情页的聊天室列表中点击某个聊天室，触发 `enterChatRoom(chatId, name)`。
2. 群聊界面右上角显示"⋯ 详情"按钮（点击后弹出聊天室详情弹窗 3.2.5.4.5）。
3. 前端发送 `GET /api/groups/<chat_id>/messages` 加载聊天记录。
4. 启动 2 秒轮询定时器，持续调用 `loadGroupMessages()`。
5. 用户输入文字，调用 `POST /api/groups/<chat_id>/send` 发送。
6. 系统消息（创建聊天室、退出聊天室、邀请、踢出、公告）在聊天界面居中显示，不使用气泡样式。
7. 消息发送者名称可点击/右键点击，触发成员信息弹窗。

---

### 3.2.5.7 成员信息交互

#### 3.2.5.7.1 成员信息弹窗

系统提供一个统一的成员信息弹窗（`memberInfoModal`），用于展示用户信息和执行相关操作。

**触发方式：**

| 触发位置 | 事件类型 | 调用函数 |
|----------|----------|----------|
| 聊天室详情弹窗中的成员列表 | 左键点击成员 | `showMemberInfo(this)` |
| 群聊消息气泡上的发送者名称 | 左键或右键点击 | `onclick` / `oncontextmenu` |
| 私聊消息气泡上的发送者名称 | 左键或右键点击 | `onclick` / `oncontextmenu` |
| 群组侧栏成员列表中的成员项 | 右键点击 | `oncontextmenu` |
| 私聊界面右上角的"⋯ 详情"按钮 | 左键点击 | `showMemberInfoFromPrivate()` |

**弹窗内容：**

| 区域 | 内容 |
|------|------|
| 头像 | 成员姓名首字符，圆形渐变背景 |
| 姓名 | 成员真实姓名 |
| 学号/工号 | 成员的 `uid` |
| 角色 | 学生/教师/管理员（中文映射） |
| 简介 | `description` 字段内容，来自 `GET /api/user/{uid}` |
| "💬 聊天"按钮 | 关闭弹窗并跳转到与该成员的私聊界面 |
| "拉黑"/"取消拉黑"按钮 | 切换黑名单状态，按钮样式随状态变化（拉黑=红色，取消拉黑=灰色） |

#### 3.2.5.7.2 上下文菜单行为

- 使用 `oncontextmenu` 事件监听，调用 `preventDefault()` 阻止浏览器原生右键菜单。
- 统一调用成员信息弹窗，不单独实现自定义上下文菜单。
- 覆盖范围：消息气泡中的发送者名称、群组侧栏成员列表项。

### 3.2.5.10 系统群组规则

系统在用户登录时自动调用 `ensure_default_groups(uid)` 创建以下系统群组：

| 群组名称 | `category` | 创建条件 | 成员范围 |
|----------|-----------|----------|---------|
| 即时聊天 | `即时聊天` | 始终创建 | 所有非好友用户（排除自己） |
| 私聊 | `私聊` | 始终创建 | 好友列表中的用户 |
| 课程 | `课程` | 仅当用户有课程数据时创建 | 学生：选修课程；教师：教授课程 |

**课程群组特殊规则：**
- **数据来源**：系统启动时从 `lessons.json` 文件导入课程数据到 `lesson` 和 `lesson_stu` 表。
  - `lesson` 表：课程 ID、课程名、教师学号、上课时间（星期+节次+周数）、地点
  - `lesson_stu` 表：课程 ID ↔ 学生学号的关联关系
- 学生角色：从 `lesson_stu` 表获取选修的课程列表。
- 教师角色：从 `lesson` 表获取教授的课程列表。
- 每门课程创建一个共享聊天室（`groups_chat`），聊天室命名为 `"{课程名}聊天室"`，`group_id` 格式为 `chat_{lesson_id}`。
- 当前用户自动加入该课程的聊天室，角色为 `member`。
- 聊天室关联到课程群组容器（通过 `user_group_chats`）。

### 3.2.5.11 远期规划：自动群组创建与成员同步（待实现）

本节描述计划中但**尚未实现**的功能，旨在与学校官方数据源对接，实现群组的自动化管理。

#### 3.2.5.11.1 数据源对接

系统计划对接以下三个官方数据源：

| 数据源 | 内容 | 用途 |
|--------|------|------|
| 学生录取名单 | 年级、专业、班级、学生信息 | 创建班级群、年级群 |
| 课程选课结果 | 课程、选课学生、授课教师 | 创建课程群 |
| 校园活动报名表 | 活动、报名人员 | 创建活动群 |

同步频率：每日凌晨 00:00 - 01:00。

#### 3.2.5.11.2 自动创建群组

系统将自动创建以下三类群组（均为系统群组）：

1. **班级群**：按年级、专业、班级划分，命名格式 `"XXXX级XX专业XX班"`，自动包含该班所有学生、班主任、辅导员，设置班主任和辅导员为群管理员。
2. **课程群**：按课程名称、授课教师划分，命名格式 `"《XXXX》课程群-授课教师XXX"`，自动包含所有选课学生和授课教师，设置授课教师为群管理员。
3. **年级群**：按年级、专业划分，命名格式 `"XXXX级XX专业年级群"`，自动包含该年级专业所有学生和年级辅导员，设置年级辅导员为群管理员。

所有自动创建的群组在创建后向成员发送系统通知。

#### 3.2.5.11.3 成员自动调整

当官方数据源发生变更时，系统自动执行以下操作：

| 数据变更 | 自动操作 |
|----------|----------|
| 学生退课 | 从对应课程群移除，通知学生和群管理员 |
| 学生转专业 | 从原班级/年级群移除，加入新班级/年级群，通知相关管理员 |
| 学生退学 | 从所有关联群组移除，通知相关管理员 |
| 活动报名新增 | 将报名人员加入对应活动群 |
| 活动取消报名 | 从对应活动群移除 |

所有调整由系统自动完成，无需人工干预。

### 3.2.5.13 数据约束

| 约束项 | 规则 |
|--------|------|
| 私聊消息表 - `messages.id` | 自增主键 |
| 群聊消息表 - `group_messages.id` | 自增主键 |
| 聊天室成员 - `group_members` | 主键 `(group_id, uid)` |
| 群组容器成员 - `user_group_members` | 主键 `(group_id, uid)` |
| 群组-聊天室关联 - `user_group_chats` | 主键 `(group_id, chat_id)` |
| 好友关系 - `friends` | 主键 `(uid, friend_uid)` |
| 黑名单 - `blacklist` | 主键 `(uid, blocked_uid)` |
| 课程 - `lesson` | `lesson_id` 主键 |
| 课程学生 - `lesson_stu` | 主键 `(lesson_id, stu_uid)` |
| 消息时间戳 | Unix 时间戳（秒），`time.time()` 生成 |
| 全局上传大小 | 最大 500MB（`MAX_CONTENT_LENGTH`） |
| 系统消息 sender | 固定为 `"system"` |
| 撤回时限 | 消息发送后 120 秒内 |
| 用户简介长度 | 最大 200 字符（前端限制） |

### 3.2.5.14 安全性说明

| 安全措施 | 说明 |
|----------|------|
| 聊天室访问控制 | 只有 `group_members` 中的成员可读取和发送消息 |
| 群组容器访问控制 | 只有 `user_group_members` 中的成员可查看详情 |
| 操作权限控制 | 仅群主/创建者可执行踢出、删除等敏感操作 |
| 文件上传安全 | 使用 `secure_filename` 清理文件名，限制上传大小 |
| 拉黑过滤 | 被拉黑用户的消息在前端被过滤，不显示 |
| 用户公开信息 | 仅通过 `GET /api/user/{uid}` 返回有限公开信息（不含密码等敏感字段） |
