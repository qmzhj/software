## 步骤一：后端职位标签按聊天室类型过滤

### 修改位置

`app.py` — `chat_room_detail()` 函数（约 line 2321-2340）

### 当前问题

目前 positions 查询对所有聊天室类型一视同仁：每个成员都会查询 `class_positions` 和 `lesson_positions`，导致课程聊天室中显示班级干部标签，班级聊天室中显示课代表标签等混乱情况。

### 修改内容

根据聊天室类型动态控制职位查询逻辑：

```
chat_room_detail 中按类型分支:
  ├─ 课程聊天室 (is_course) → 仅查询 teacher marker + lesson_positions
  ├─ 班级聊天室 (category='班级') → 仅查询 class_positions，且 class_id 匹配当前聊天室
  ├─ 赛事聊天室 (is_event) → 不查询任何职位
  └─ 普通聊天室 → 不查询任何职位
```

### 关键实现细节

**班级聊天室的 class_id 提取**：
- `group_id` 以 `'chat_class_'` 开头，去掉前缀即为 `class_id`
- 即 `class_id = group_id[11:]`（len(`'chat_class_'`) = 11）
- 需要在函数开头检测 `is_class`，与 `is_course`、`is_event` 并列

**班级聊天室的 class_positions 查询**（仅限该班级）：

```python
if is_class:
    rows = conn.execute('''SELECT cp.position_name
                           FROM class_positions cp
                           WHERE cp.class_id=? AND cp.uid=?''',
                        (class_id, m['uid'])).fetchall()
    for r in rows:
        positions.append({'type':'class','label':r['position_name']})
```

注意：班级聊天室的职位标签只显示职位名（如"班长"），不需要显示班级名（因为上下文已经是该班级）。

**课程聊天室保留现有逻辑**（teacher marker + lesson_positions），但去掉对 `class_positions` 的查询。

**响应的补充字段**：
- 班级聊天室：`result['class_id'] = class_id`，供前端两栏式展示使用
- 班级聊天室：`result['class_name']`，从 `classes` 表查询

### 验证方法

分别打开四种聊天室的详情弹窗，确认：
1. 课程聊天室：教师显示 👑教师，课代表显示 📖课代表，无班干部标签
2. 班级聊天室：班干部显示职位名，无课代表标签
3. 普通聊天室：无任何职位标签
4. 赛事聊天室：无任何职位标签

## 步骤二：前端通用角色标签恢复

### 修改位置

`static/groups.html` — `showChatDetail()` 函数（约 line 1436-1478）

### 当前问题

之前误删了 roleLabel 逻辑，当前聊天室详情成员列表中不显示任何角色标签（🔑群主/🛡️管理员/🏆负责人）。

### 修改内容

在成员列表的每个成员名称旁加上对应的角色标签，按聊天室类型区分：

| 聊天室类型 | `role='admin'` | `role='manager'` |
|-----------|----------------|-------------------|
| 普通聊天室 | `🔑群主` | `🛡️管理员` |
| 课程聊天室 | `👑教师`（替代 🔑群主） | `🛡️管理员` |
| 班级聊天室 | `🔑群主` | `🛡️管理员` |
| 赛事聊天室 | `🏆负责人`（替代 🔑群主） | `🛡️管理员` |

### 实现方式

在 `showChatDetail()` 的 map 回调中，添加 roleLabel 变量：

```javascript
// 角色标签（按聊天室类型区分）
let roleLabel = '';
if (m.role === 'admin') {
  if (isCourse) roleLabel = ' 👑教师';
  else if (isEvent) roleLabel = ' 🏆负责人';
  else roleLabel = ' 🔑群主';
} else if (m.role === 'manager') {
  roleLabel = ' 🛡️管理员';
}
```

在成员名称渲染处拼接：

```javascript
'<span style="font-weight:500;font-size:13px;">' + escapeHtml(m.name) + roleLabel + '</span>'
```

### 课程聊天室的特殊情况

课程聊天室中，教师（`role='admin'`）显示 `👑教师` 而非 `🔑群主`。但如果有其他 `role='admin'` 的非教师用户，是否要显示 `🔑群主`？目前课程聊天室的 admin 只有教师一人，此情况暂不处理。

## 步骤三：班级聊天室两栏式展示

### 修改位置

- `static/groups.html` — `showChatDetail()` 函数
- `app.py` — `chat_room_detail()` 函数（补充 class_name 字段）

### 前置依赖

步骤一已完成，`chat_room_detail` 已返回 `class_id` 和 `class_name`，每个成员的 `positions` 中已包含该班级的班干部职位。

### 实现方案

#### 后端补充

在 `chat_room_detail()` 的 `is_class` 分支中返回班级名称：

```python
if is_class:
    class_id = group_id[11:]
    cls = conn.execute('SELECT class_name FROM classes WHERE class_id=?', (class_id,)).fetchone()
    result['class_id'] = class_id
    result['class_name'] = cls['class_name'] if cls else class_id
```

#### 前端展示

`showChatDetail()` 中增加 `isClass` 判断，渲染时分两栏：

```javascript
const isClass = detail.creator === 'system' && detail.category === '班级';

// 分栏逻辑
let cadreMembers = [];  // 有 class 类型 positions 的成员
let regularMembers = []; // 无 positions 的普通成员

detail.members.forEach(m => {
  const hasCadre = (m.positions || []).some(p => p.type === 'class');
  if (hasCadre) cadreMembers.push(m);
  else regularMembers.push(m);
});

// 渲染两栏
let html = '';
if (cadreMembers.length > 0) {
  html += '<div style="padding:6px 4px;font-size:12px;color:var(--text-muted);border-bottom:1px solid var(--border);">👥 班干部</div>';
  html += cadreMembers.map(m => renderMemberItem(m)).join('');
}
if (regularMembers.length > 0) {
  html += '<div style="padding:6px 4px;font-size:12px;color:var(--text-muted);border-bottom:1px solid var(--border);">👤 班级成员</div>';
  html += regularMembers.map(m => renderMemberItem(m)).join('');
}
memberList.innerHTML = html;
```

建议将单个成员的 HTML 渲染抽取为一个内联函数 `renderMemberItem(m)`，避免代码重复。

#### 班级聊天室的权限控制

- 不显示"设为管理员"和"设为课代表"按钮
- 创建聊天室时已从 `class_positions` 将班长/兼班/兼助/辅导员设为 `admin`
- 群主（admin）仍然可以踢出成员

### 两栏式与排序规则的交互

- 班干部栏内部：按 `class_positions` 中的顺序或成员加入时间排序
- 班级成员栏内部：按加入时间排序
- 班干部栏整体在班级成员栏上方

## 执行顺序

```
步骤一 (后端过滤) → 步骤二 (前端角色标签) → 步骤三 (班级两栏式)
```

步骤一必须先做，因为后端数据变了前端才能正确渲染。步骤二和步骤三都依赖步骤一的数据，但二者互不依赖。
