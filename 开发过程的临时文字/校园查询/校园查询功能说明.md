# 校园查询功能说明

## 概述

校园查询模块提供师生日常所需的校园信息检索功能，包括用户搜索、赛事活动、辅导值班、办公室查询、课程安排等。数据通过 `_seed_data()` 初始化填充默认样例，课程数据通过 `lessons.json` 文件加载。

所有功能集中在 `/query` 页面和对应的 API 端点中。

## 各功能详情

### 1. 用户搜索

- **数据表**: `users`（uid, name, password, role, locked, ...）
- **接口**: `GET /api/search/users?q={关键字}`
- **描述**: 按学号（uid）或姓名（name）模糊搜索用户，返回最多 50 条结果
- **前端**: 搜索框输入关键字，点击查询，结果以时间线卡片展示姓名、学号和角色
- **备注**: 不搜索已注册/未注册状态，所有用户均可搜到

### 2. 空闲教室

- **数据表**: `classrooms`（id, building, floor, seats, has_media）
- **接口**: `GET /api/classrooms/free?date=&start=&end=`
- **描述**: 返回所有教室列表，含教学楼、楼层、座位数、多媒体设备
- **当前约束**: 
  - API 返回全部教室，**不根据传入的 date/start/end 参数进行实际占用冲突过滤**
  - 前端 tab 配置已注释（`//*/`），该功能在 UI 中不可见
  - `course_schedule` 表虽存有课程占用数据，但未与教室查询做联表校验
- **种子数据**: 6 间教室（A101/A102/B201/B202/C301/C302）

### 3. 赛事活动

- **数据表**: `events`（id, name, type, start_time, end_time, location, target, organizer, description）
- **接口**: `GET /api/events`
- **描述**: 返回所有校园活动，按开始时间升序排列
- **前端**: 切换到该 tab 时自动加载，时间线卡片展示活动名、类型、时间、地点、面向对象、描述
- **种子数据**:
  - 秋季运动会（体育赛事）
  - 校园十大歌手（文艺活动）
  - 人工智能讲座（学术讲座）

### 4. 辅导值班

- **数据表**: `tutor_duty`（id, teacher_name, teacher_uid, college, duty_date, start_time, end_time, location, contact）
- **接口**: `GET /api/tutor_duty?date={日期}&college={学院}`
- **描述**: 按日期和学院查询教师辅导值班安排。college 参数可选，不传则按日期查询全部
- **前端**: 提供日期输入框和学院输入框，结果卡片展示教师、学院、值班时间段、地点、联系电话

### 5. 办公室查询

- **数据表**: `teacher_office`（uid, name, college, title, office, phone）
- **接口**: `GET /api/teacher_office?college={学院}`
- **描述**: 按学院查询教师办公室信息。college 参数可选，不传则返回全部
- **前端**: 提供学院输入框，结果卡片展示教师姓名、职称、学院、办公室、电话

### 6. 课程安排

- **数据表**: `course_schedule`（id, course_name, teacher, classroom_id, day_of_week, start_time, end_time）
- **接口**: `GET /api/course_schedule?classroom={教室编号}`
- **描述**: 按教室编号查询课程安排。classroom 参数可选，不传则返回全部
- **前端**: 提供教室编号输入框，结果卡片展示课程名、教师、时间段、星期、教室

### 7. 公告（伪条目）

- 前端 `queries` 配置中声明了此 tab，但其 form 和按键处理函数与"课程安排"相同（调用 `loadCourses()`）
- **实质上是无效条目**，点击后实际展示的是课程安排结果
- 后端 `announcements` 表存在但**无独立查询 API 端点**

## 数据初始化

### 种子数据 (`_seed_data`)

在首次启动时填充以下默认数据：

| 表 | 初始记录数 | 数据来源 |
|---|-----------|---------|
| classrooms | 6 | 代码硬编码 |
| course_schedule | 4 | 代码硬编码 |
| events | 3 | 代码硬编码 |
| tutor_duty | 2 | 代码硬编码 |
| teacher_office | 3 | 代码硬编码 |

### 课程数据加载 (`_load_lessons_from_json`)

从项目根目录下的 `lessons.json` 文件读取课程数据，写入 `lesson` 和 `lesson_stu` 表。这两个表不直接服务于查询页面，而是用于**系统群组的自动创建**（`ensure_default_groups` 据此为用户创建课程群组和课程聊天室）。

## 已知问题

1. **空闲教室查询无实际过滤逻辑**：API 返回全部教室而非真正空闲的教室，数据与 `course_schedule` 表未打通
2. **公告 tab 无效**：前端配置存在但行为与课程安排重复，后端无独立 API
3. **所有查询接口无分页**：结果集全量返回，数据量大时存在性能隐患
4. **空参数行为不一致**：部分接口（events）无参数，部分接口参数全为空时返回全部数据，前端输入校验薄弱
