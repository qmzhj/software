## 赛事参与
用户可点击一个赛事后，进入赛事详情界面，内容为:
- 赛事的详细介绍栏目（起止时间，地点，详细介绍，赛事目的，附件）
- 赛事参与人栏目：
    - 用户可在其中创建小组的，寻找队友
    - 用户可设置自己创建的小组的状态为“已满员”

    - 赛事参与人栏目标头中有选项：“显示/不显示满员小组”

## 身份系统设计

### 数据模型

```sql
-- 班级表
CREATE TABLE classes (
    class_id TEXT PRIMARY KEY, -- 导入时自动生成 hash，与 lesson_id 风格一致
    class_name TEXT,       -- 如"网工一班"
    grade TEXT,            -- 2024
    major TEXT,            -- 网络工程
    department TEXT,       -- 计算机学院
    level TEXT DEFAULT 'class'  -- 'class' 班级群 | 'grade' 年级群
);

-- 班干部职位（附加标记，不影响 users.role）
CREATE TABLE class_positions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    class_id TEXT NOT NULL,
    uid TEXT NOT NULL,
    position_name TEXT NOT NULL,  -- '班长'|'团支书'|'学委'|'组委'|'心委'|'兼班'|'兼助'|...
    FOREIGN KEY (class_id) REFERENCES classes(class_id),
    FOREIGN KEY (uid) REFERENCES users(uid)
);

-- 课程职位表（关联课程而非班级），与 class_positions 结构一致
-- 数据由教师在课程聊天室中自行设置，不从 JSON 加载
CREATE TABLE lesson_positions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    lesson_id TEXT NOT NULL,
    uid TEXT NOT NULL,
    position_name TEXT NOT NULL,  -- '课代表'|'助教'|...
    FOREIGN KEY (lesson_id) REFERENCES lesson(lesson_id),
    FOREIGN KEY (uid) REFERENCES users(uid)
);

-- 班级成员关联表（class_id → 学生uid），与 lesson_stu 命名一致
CREATE TABLE class_stu (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    class_id TEXT NOT NULL,
    uid TEXT NOT NULL,
    FOREIGN KEY (class_id) REFERENCES classes(class_id),
    FOREIGN KEY (uid) REFERENCES users(uid)
);
```
其中班级数据从class.json文件读取，参考`自动创建课程群组要求.md`中lessons.json的数据格式设计，json文件中数据格式为
```
    {
        "class_name": "网工一班",
        "grade": "2024",
        "major": "网络工程",
        "department": "计算机学院",
        "class_cadre":{"班长":202421326578, "团支书":202421326579, ......(其它班干部)}
        "class_member": [
            "202421326577","202421326578","202421326579","202421326580",
            "202421326581","202421326582","202421326583","202421326584",
            "202421326585","202421326586","202421326587","202421326588"
        ]
    },
    {
        "class_name": "2024级计算机学院",
        "grade": "2024",
        "major": "无",
        "department": "计算机学院",
        "class_cadre":{"年级长":202421326579, ......(其它班干部)}
        "class_member": [
            "202421326577",.......
        ]
    },

    ...............（其它班级）
```

### JSON→数据库映射说明

JSON 中的 `class_cadre` 数据导入时写入 `class_positions` 表，映射关系：
```
class_cadre: {"班长": 202421326578, "团支书": 202421326579}
  → class_positions: (class_id='网工一班', uid='202421326578', position_name='班长')
                      (class_id='网工一班', uid='202421326579', position_name='团支书')
```
`class_member` 数组导入 `class_stu` 表，每条为 `(class_id, uid)` 映射。

### 设计思路

- **`users.role`（student/teacher/manager）不变**，班干部和课代表只是附加标记，不走权限继承
- 职位类型用字符串存，新增职位直接加数据，不改表结构
- 课代表关联的是课程（`lesson_id`）而非班级，与班干部职责域天然分开

### 搜索实现

#### 搜索入口

改造现有搜索框（`/api/search/users`），替换为带搜索模式下拉菜单的搜索栏。不再使用原来单一的模糊搜索方式。

#### 搜索模式切换

用户通过下拉菜单选择搜索模式，目前支持五种模式：

| 搜索模式 | 搜索框提示 | 实现路径 |
|---------|-----------|---------|
| 按学号/姓名 | 输入学号或姓名 | `users` 表模糊匹配 |
| 按课程 | 输入课程全名 | `lesson`（教师）+ `lesson_stu`（学生）→ 再查 `lesson_positions` 标注职位 |
| 按班级 | 输入班级名（如"网工一班"） | `class_stu` → 查出该班所有学生 uid |
| 按身份 | 下拉选择身份（班长/课代表/...） | `class_positions.position_name` / `lesson_positions.position_name` 匹配 |
| 组合搜索 | 班级 + 身份联合查询 | 先按班级查出学生，再过滤身份，如"网工一班 班长" |

#### 返回格式

搜索结果返回用户列表时，附带身份标签：

```json
[
    {
        "uid": "202421326578",
        "name": "张三",
        "role": "student",
        "tags": ["班长", "课代表-数据结构"]
    }
]
```

- `tags` 数组，包含该用户在所有班级/课程中的职位
- 前端以徽标（badge）形式在每个用户旁展示身份标签

### 为什么这个方案够用

- 课程 demo 项目不需要完整的 RBAC 权限体系
- 四张简单表，CRUD 代码量少
- 可演示性足够：搜索"网工一班班长"能正确返回用户及其身份标签
- 如需扩展（如班长有某些管理权限），增加逻辑判断即可，表结构不用动

### 聊天室详情界面设计

根据聊天室类型，详情界面采用不同的成员展示和操作逻辑。后端通过 `creator` 和 `category` 区分类型：

| 聊天室类型 | `creator` | `category` | 识别方式 |
|-----------|----------|-----------|---------|
| 普通聊天室 | 用户 uid | 自定义 | 用户创建，自定义分类 |
| 课程聊天室 | `system` | `课程` | 自动创建，关联课程 |
| 班级聊天室 | `system` | `班级` | 自动创建，关联班级 |

#### 普通聊天室

现有逻辑不变：
- 成员平铺展示
- 群主/管理员可进行 **设为管理员** / **取消管理** / **踢出** 操作
- 管理员按钮文字为"设为管理"

#### 课程聊天室

- 成员平铺展示，不分区
- **教师**（`lesson.teacher_uid`）和**课代表**（`lesson_positions`）在成员列表中显示职位标签（如 `👑教师`、`📖课代表`）
- 管理员操作栏中，以 **"设为课代表"** 按钮替换 **"设为管理员"** 按钮
  - 点击后调用 `POST /api/lesson-positions/set`，自动创建 `lesson_positions` 表项（`lesson_id`, `uid`, `position_name='课代表'`）
  - 取消课代表同理，调用 `POST /api/lesson-positions/unset`，删除对应表项
- `lesson_positions` 数据由教师在聊天室详情界面自行设置，不从 JSON 加载
- 系统自动创建的课程聊天室中，`lesson.teacher_uid` 的教师自动设为 `group_members.role='admin'`（还未实现）
- 课代表只记录在 `lesson_positions` 中，不修改 `group_members.role`

#### 班级聊天室

- 成员列表分两个栏目展示：

  | 栏目 | 包含人员 | 职位标签 |
  |------|---------|---------|
  | 班干部 | `class_positions` 中有职位的学生 | 显示具体职位（班长/团支书/兼班/兼助...） |
  | 班级成员 | `class_stu` 中其余普通同学 | 无 |

- 管理员权限：创建班级聊天室时，查询 `class_positions` 中 `兼班`、`兼助`、`班长`，将 `group_members.role` 设为 `admin`（还未实现）
- 班级聊天室不显示"设为管理员"或"设为课代表"按钮

## 现有课程相关表说明

系统中已有的两张课程表，与身份系统配合使用：

### lesson（课程表）

```sql
CREATE TABLE IF NOT EXISTS lesson (
    lesson_id TEXT PRIMARY KEY,      -- 自动生成 hash
    lesson_name TEXT,                -- 课程名
    teacher_uid TEXT,                -- 授课教师 uid
    schedule_weekday TEXT,           -- 星期几
    schedule_period TEXT,            -- 第几节（如 "1-2"）
    schedule_weeks TEXT,             -- 上课周数（如 "1-16"）
    location TEXT                    -- 上课地点
);
```

### lesson_stu（课程-学生关联表）

```sql
CREATE TABLE IF NOT EXISTS lesson_stu (
    lesson_id TEXT,
    stu_uid TEXT,
    PRIMARY KEY(lesson_id, stu_uid)
);
```

### 数据来源

从 `lessons.json` 读取，格式如下：

```json
{
    "lesson_name": "数据结构",
    "teacher_uid": "202421326500",
    "schedule_weekday": "星期三",
    "schedule_period": "1-2",
    "schedule_weeks": "1-16",
    "location": "北504",
    "stu_uids": ["202421326577", "202421326578", ...]
}
```

### 与身份系统的关系

- 课程聊天室由 `ensure_default_groups()` 遍历 `lesson`/`lesson_stu` 自动创建
- `lesson.teacher_uid` 的教师自动设为聊天室管理员（还未实现）
- `lesson_positions` 扩展存储课代表/助教等课程职位，同样在创建时设为管理员（还未实现）
