## Bug 描述

### 1. 转发消息后目标接收方看不到消息

**场景：** 右键消息 → 转发 → 选择目标（聊天室或用户）→ 点击"逐条转发"或"合并转发"

**现状：** 发送方弹出"转发成功"，但目标聊天室/用户的界面中没有出现转发的消息

**期望：**
- 逐条转发：对每条消息直接调用目标聊天室的 `POST /api/groups/{chatId}/send` 或私聊的 `POST /api/send`，目标方应通过 SSE 实时收到消息
- 非文本消息（图片/视频/文件）：当前逐条转发时发送的是 `'[转发] ' + file_name` 纯文本，应保持原消息类型和文件进行转发
- 合并转发：以纯文本 `📩 合并转发\n发送者: 消息内容` 发送，这种方式能正常显示但需确认接收方确实能看到（Bug 3 讨论点击查看功能）

**可能原因：** SSE 通知后前端 `loadGroupMessages()` / `loadPrivateMessages()` 重新拉取消息但未正确渲染；或后端发送接口返回成功但未正确写入数据库

---

### 2. 撤回消息后提示文案与展示样式不对

**场景：** 右键消息 → 撤回

**现状：** 撤回后原消息气泡内显示斜体灰色"已撤回"字样

**期望：** 根据需求文档，撤回后应向聊天中插入一条消息 `"xxx（撤回用户）撤回了一条消息"`，显示为居中灰色系统消息（类似群成员加入/离开的提示样式），而非在原气泡内修改内容

**注意：** 当前后端 `revoke` 接口仅设置 `revoked=1`，未插入新的系统类型消息记录；前端 `renderMessageContent` 对 `revoked` 消息返回 `'<div style="font-style:italic;opacity:.6">已撤回</div>'` 显示在气泡内。需要同时在客户端显示撤回用户名称

---

### 3. 合并转发的聊天记录包不可点击展开查看

**场景：** 选择多条消息 → 合并转发到聊天 → 接收方看到合并转发消息

**现状：** 合并转发以纯文本形式发送，内容为 `📩 合并转发\n张三: 消息1\n李四: 消息2`，接收方看到的是普通文本消息，不可点击

**期望：** 根据需求文档，合并转发应生成一个特殊的"聊天记录包"：
- 在聊天界面中显示为一条可点击的消息（如卡片样式或带底色的消息块）
- 左键点击后弹出一个新界面/模态框，逐条展示被转发的消息，每条显示发送者名称和消息内容
- 图片/视频/文件类型的消息在合并转发中显示为 `[图片]`/`[视频]`/`[文件]` 占位文案，不可点击查看

**实现思路：**
- 方案 A：后端新增消息类型 `msg_type='merge_forward'`，`content` 中存储 JSON 格式的转发数据，前端据此渲染可点击的卡片和展开界面
- 方案 B：沿用纯文本格式发送，前端检测消息内容以 `📩 合并转发` 开头时特殊渲染为可点击卡片
