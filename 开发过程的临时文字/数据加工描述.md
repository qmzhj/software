数据加工描述

## 3.2.1 用户注册数据加工

注册功能面向系统预置在 users 表中的师生账号。输入数据为用户通过注册表单提交的学工号（uid）、姓名（name）、密码（password）、确认密码（confirm）、手机号（phone，非必填）。前端对密码执行格式预校验，校验规则为正则表达式 ^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$，密码必须包含至少1个小写字母、1个大写字母、1位数字且总长度不低于8位。前端校验两次密码输入是否完全一致。所有前端校验通过后，前端发送 POST /api/register 请求将数据提交至服务端。服务端首先执行二次参数校验，确认密码格式合法且两次密码一致。然后以 uid 为唯一检索键查询 users 表进行三层身份核验：账号存在性核验（判断数据库中是否存在对应 uid 的预置用户）、姓名匹配核验（比对用户录入 name 与数据库预置 name 字段）、注册状态核验（确认 registed 字段为 0）。三层核验全部通过后，服务端根据 uid 编码规则通过正则表达式判定用户角色：匹配 `^202\d{9}` 的学生学号判定为 student、匹配 `^[12][0-9]{10}` 的博士或硕士学号判定为 student、匹配 `^TE\d{7}` 等教职工工号判定为 teacher、匹配 `^ADMIN\d{3}` 等管理员账号判定为 manager。角色判定后，服务端使用 hashlib.sha256 算法对密码进行加密，加密公式为 SHA256(password + "CampusFakeSalt2024!")，结果输出为十六进制小写字符串。服务端执行 UPDATE users SET password=加密后密码, phone=用户录入手机号, registed=1 WHERE uid=? 更新用户数据。服务端调用 ensure_default_groups(uid) 函数为当前用户创建三类系统预设群组（即时聊天、私聊、课程）。注册成功时返回 HTTP 201 及 {message: '注册成功'}。失败时根据异常场景返回对应状态码：密码格式不合法或两次密码不一致返回 400，学工号不存在或姓名不匹配或账号已注册返回 409，数据库异常返回 500。

## 3.2.2 用户登录数据加工

输入数据为用户通过登录表单提交的学工号（uid）和密码（password）。服务端接收 POST /api/login 请求后，以 uid 为检索键查询 users 表。uid 不存在时返回 400 {error: '账号不存在'}。查询到用户后检查 locked 字段，locked 为 1 时比较当前时间与 unlock_time，当前时间未达到 unlock_time 时返回 403 {error: '账户已锁定，请30分钟后重试'}。locked 为 1 且当前时间已超过 unlock_time 时，服务端执行 UPDATE users SET locked=0, login_fails=0 解除锁定。密码验证时，服务端使用 SHA256(password + "CampusFakeSalt2024!") 对用户输入密码加密，与数据库中存储的加密密码比对。密码不匹配时累加 login_fails 字段，login_fails 达到 5 时设置 locked=1 并设置 unlock_time=当前时间+1800秒，返回 403 {error: '账户已锁定，请30分钟后重试'}。密码匹配时调用 secrets.token_hex(16) 生成32位十六进制随机字符串作为 Token，将 Token 存入全局 tokens 字典（键为 Token、值为用户 uid），重置 login_fails=0，返回 200 及 {token, uid, name, role}。tokens 字典存储在服务端内存中，服务重启后所有登录状态失效。

## 3.2.3 消息发送数据加工

消息发送分为私聊消息和群聊消息两类。

### 3.2.3.1 私聊消息发送

输入数据为接收者 uid（receiver）和消息内容（content，上限2000字符）。前端在弹出式私聊窗口中输入消息内容，校验内容不为空且不超过2000字符后发送 POST /api/send 请求。服务端接收请求后执行 INSERT INTO messages (sender, receiver, content, timestamp) VALUES (当前用户uid, receiver, content, now)，其中 sender 为当前登录用户 uid，timestamp 为当前 Unix 时间戳。消息写入成功后返回 {message: '发送成功'}。前端采用乐观渲染策略，不等待服务端响应即将消息追加到消息列表末尾并滚动到底部。消息加载通过 GET /api/messages?uid=对方uid 接口实现，服务端执行 SELECT * FROM messages WHERE (sender=当前用户uid AND receiver=对方uid) OR (sender=对方uid AND receiver=当前用户uid) ORDER BY timestamp ASC，返回全部消息记录，不分页。每条消息包含 id、sender、receiver、content、timestamp、is_revoked 字段。消息撤回通过 POST /api/messages/revoke/{messageId} 实现，服务端执行 UPDATE messages SET is_revoked=1 WHERE id=? AND sender=当前用户uid AND ? - timestamp < 120，撤回时限为消息发送后120秒内，超过时限返回 400，非发送者操作返回 403。

### 3.2.3.2 群聊消息发送

输入数据为聊天室 ID（chatId）和消息内容（content，上限2000字符）。用户在聊天室消息输入框中输入文字后发送 POST /api/groups/{chatId}/send 请求。服务端执行 INSERT INTO group_messages (group_id, sender, content, timestamp, msg_type) VALUES (chatId, 当前用户uid, content, now, 'text')。群聊消息加载通过 GET /api/groups/{chatId}/messages 实现，服务端返回 group_messages 表中该 group_id 的全部消息记录，不分页。每条消息包含 sender、sender_name、content、timestamp、msg_type 字段。msg_type 为 'system' 的系统消息由服务端在聊天室创建、成员加入、成员退出、解散等操作时自动写入。

## 3.2.4 公告发布数据加工

输入数据为标题（title，1-100字符）、正文（content，1-10000字符）、发布单位（unit）、附件文件（attachments，可选）。服务端接收 POST /api/announcements 请求。请求体以 multipart/form-data 格式提交，包含 title、content、unit 字段及可选的文件附件。服务端校验当前用户角色，角色为 student 时返回 403 {error: '学生不能发布公告'}。校验标题和正文长度，标题为空或超过100字符时返回 400，正文字符数小于1或超过10000字符时返回 400。附件文件上传至 static/uploads/ 目录，文件名格式为 {timestamp}_{原始文件名}，文件大小上限为 500MB。服务端执行 INSERT INTO announcements (publisher, unit, title, content, attachments, created_at) VALUES (当前用户uid, unit, title, content, 附件路径, now) 写入公告数据。公告创建成功后返回 201 及 {message: '公告创建成功', announcement: {id, title, content, publisher_name, unit, created_at}}。公告修改通过 PUT /api/announcements/{id} 实现，仅发布者可修改，执行 UPDATE announcements SET title=?, content=?, modified_at=now, modifier=? WHERE id=?。公告删除通过 DELETE /api/announcements/{id} 实现，仅发布者可删除。公告列表通过 GET /api/announcements 获取，返回所有公告按 created_at 降序排列。

## 3.2.5 系统群组自动创建数据加工

系统群组自动创建功能在用户注册成功时由 ensure_default_groups(uid) 函数触发执行，非定时任务。输入数据为当前注册用户的 uid。函数首先在 user_groups 表中检查是否存在 group_id 为 sys_im_{uid}、sys_private_{uid}、sys_courses_{uid} 的记录。不存在时依次创建三类系统预设群组。即时聊天群组（sys_im_{uid}）名称为「即时聊天」，group_type 为 system，成员列表不在 user_group_members 中存储，每次查询时通过 SELECT uid FROM users WHERE uid != 当前用户uid AND uid NOT IN (SELECT friend_uid FROM friends WHERE uid=当前用户uid) 动态计算。私聊群组（sys_private_{uid}）名称为「私聊」，group_type 为 system，成员列表动态计算为当前用户在 friends 表中的好友。课程群组（sys_courses_{uid}）名称为「课程」，group_type 为 system，创建后进一步按课程匹配创建聊天室。课程聊天室关联逻辑为：根据用户角色查询课程数据，学生角色查询 lesson_stu 表获取选修课程列表，教师角色查询 lesson 表获取授课课程列表。对每门课程，按课程名匹配 groups_chat.name，找到对应聊天室则建立 user_group_chats 关联，未找到则先创建聊天室（INSERT INTO groups_chat）再建立关联。四类虚拟群组「未分类」（sys_uncategorized_{uid}）不写入 user_groups 表，仅在前端群组列表展示时通过动态查询生成。

## 3.2.6 权限验证数据加工

输入数据为用户请求中携带的 Token。服务端通过 @token_required 装饰器对需要认证的 API 路由进行拦截。装饰器从请求头中提取 Authorization 字段值，去除 "Bearer " 前缀后得到 Token 字符串。服务端以 Token 为键在全局 tokens 字典中查找对应用户 uid。查找失败时返回 401 {error: '请先登录'}。查找成功时将 uid 对应的用户数据行（sqlite3.Row 对象）赋值给 g.current_user，供后续路由处理函数使用。角色通过 uid 编码规则的正则表达式匹配判定，不依赖独立的 Permission 表或 RolePermission 表。角色分为 student（学生）、teacher（教师）、manager（管理员）三类。授权逻辑在各 API 路由中单独实现：发布公告接口校验角色不为 student、系统群组修改操作校验 group_type 不为 system、聊天室管理操作校验用户在 group_members 中的 role 字段为 admin 或 manager。

## 3.2.7 教室空闲状态查询数据加工

输入数据为查询日期（date）、开始时间（startTime）、结束时间（endTime）。服务端接收 GET /api/classrooms/free?date=YYYY-MM-DD&start=HH:MM&end=HH:MM 请求。服务端查询 classrooms 表返回所有教室记录，每条记录包含 id、building（教学楼）、floor（楼层）、seats（座位数）、media（设备信息，基于 has_media 字段返回"有"或"无"）。当前版本实现返回全部教室数据，不根据传入的日期和时间参数进行空闲状态过滤。

## 3.2.8 消息加载数据加工

私聊消息加载通过 GET /api/messages?uid=对方uid 接口实现。服务端执行 SELECT id, sender, receiver, content, timestamp, is_revoked FROM messages WHERE (sender=当前用户uid AND receiver=对方uid) OR (sender=对方uid AND receiver=当前用户uid) ORDER BY timestamp ASC，返回当前用户与指定用户之间的全部消息记录。群聊消息加载通过 GET /api/groups/{chatId}/messages 接口实现。服务端执行 SELECT gm.sender, u.name as sender_name, gm.content, gm.timestamp, gm.msg_type FROM group_messages gm JOIN users u ON gm.sender = u.uid WHERE gm.group_id=? ORDER BY gm.timestamp，返回指定聊天室的全部消息记录。两类消息加载均不分页，一次性加载全部数据。前端通过每2秒一次的 setInterval 轮询实现消息实时更新。
