# UML 活动图：即时消息收发流程（泳道图）

## 1. 图表结构
- **类型**：UML 活动图（Activity Diagram）/ 泳道图
- **布局**：横向 3 泳道，从左到右依次排列
- **泳道标题栏颜色**：
  - 发送方（前端）：蓝色
  - 后端服务：黄色
  - 接收方（前端/SSE）：绿色
- **起止节点**：顶部实心黑圆（开始），底部实心黑圆（结束）

## 2. 泳道详情与流程

### 流程一：消息发送（私聊与群聊）

#### 泳道 1：发送方（左侧）
- **节点序列**：
 1. 开始（实心圆）
 2. [进入聊天界面，输入消息或选择文件]（矩形）
 3. [点击发送]（矩形）
 4. {发送成功？}（菱形判断）
    - N → [显示错误提示]（矩形）
    - Y → 步骤 5
 5. [消息显示在聊天区域]（矩形）
 6. 结束（实心圆）

#### 泳道 2：后端服务（中间）
- **节点序列**：
 1. {发送权限校验通过？}（菱形判断，私聊：内容非空/接收方存在/未被拉黑，群聊：是聊天室成员）
    - N → 返回错误信息
    - Y → 步骤 2
 2. [保存消息到数据库]（矩形）
 3. [通过 SSE 向接收方推送新消息通知]（矩形）
 4. 结束（实心圆）

#### 泳道 3：接收方（右侧）
- **节点序列**：
 1. [SSE 连接持续监听]（矩形）
 2. [收到新消息通知，拉取最新消息]（矩形）
 3. [消息显示在聊天区域]（矩形）
 4. 结束（实心圆）

### 流程二：消息撤回

#### 泳道 1：操作者（前端）
- **节点序列**：
 1. 开始（实心圆）
 2. [右键点击已发送消息，选择"撤回"]（矩形）
 3. {有权限撤回？}（菱形判断，发送者/管理员/群主）
    - N → 菜单无撤回选项 → 结束
    - Y → 步骤 4
 4. [确认撤回]（矩形）
 5. [消息替换为撤回提示]（矩形）
 6. 结束（实心圆）

#### 泳道 2：后端服务
- **节点序列**：
 1. {未超撤回时限？}（菱形判断，普通用户2分钟，管理员不限）
    - N → 返回"超过撤回时间"
    - Y → 步骤 2
 2. [标记消息已撤回]（矩形）
 3. [通过 SSE 通知接收方刷新]（矩形）
 4. 结束（实心圆）

### 流程三：消息转发

#### 泳道 1：转发者（前端）
- **节点序列**：
 1. 开始（实心圆）
 2. [选择消息，点击"转发"]（矩形）
 3. [选择转发方式：合并转发 / 分条转发]（矩形）
 4. [选择目标（私聊对象或群聊），确认发送]（矩形）
 5. 结束（实心圆）

#### 泳道 2：后端服务
- **节点序列**：
 1. {合并转发？}（菱形判断）
    - Y → [生成含多条原文的合并卡片，写入目标消息表]（矩形）
    - N → [逐条复制原文到目标，标注原始发送者]（矩形）
 2. [通过 SSE 推送新消息]（矩形）
 3. 结束（实心圆）

# 当前功能模块描述

即时消息收发是系统的核心沟通功能，支持用户在已建立的聊天会话中，向单个接收者发起一对一聊天，或向多个接收者发起群聊消息发送，覆盖文字、图片、音频、视频、文件等多种消息类型，满足校内师生、教职工之间的多样化沟通需求。消息收发过程严格遵循加密传输规范，确保消息内容的安全性与完整性，同时兼顾传输效率与用户体验。

消息发送过程中，系统设有多层检测机制确保消息的合规性与可达性。私聊发送时，系统依次校验消息内容是否为空、接收方用户是否存在、发送方是否被接收方拉入黑名单。若发送方已被接收方拉黑，系统将拒绝发送并提示"你已被此用户拉黑"，被拉黑期间发送方无法向该用户发送任何类型消息。群聊发送时，系统首先校验发送方是否为聊天室成员，非成员发送请求将被拒绝。

消息撤回功能允许用户在一定条件下撤销已发送的消息，纠正误发内容。消息发送成功后的2分钟内，发送者可右键点击消息气泡选择撤回，撤回后消息内容替换为"XXX撤回了一条消息"的系统提示，接收方无法再查看原消息内容。群主和聊天室管理员享有特权，不受2分钟时限限制，可随时撤回任意成员的消息。

消息转发功能支持用户将聊天中的消息通过合并转发或分条转发方式分享给其他用户或群聊。合并转发将多条消息整合为一个聚合卡片发送，接收方点击卡片可逐条查看原文及发送者信息。分条转发则将每条消息作为独立消息逐一发送至目标聊天，每条消息标注来源昵称。
