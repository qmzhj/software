# UML 活动图：聊天室流程（泳道图）

## 1. 图表结构
- **类型**：UML 活动图（Activity Diagram）/ 泳道图
- **布局**：横向 3 泳道，从左到右依次排列
- **泳道标题栏颜色**：
  - 用户（前端）：蓝色
  - 后端 API：黄色
  - 数据库 / 教务平台：绿色
- **起止节点**：顶部实心黑圆（开始），底部实心黑圆（结束）

## 2. 泳道详情与流程

### 流程一：聊天室自动创建（课程数据驱动）

#### 泳道 1：学校教务平台（右侧）
- **节点序列**：
 1. 开始（实心圆）
 2. [提供课程选课结果数据（lesson、lesson_stu）]（矩形）
 3. [每日同步至系统数据库]（矩形）
 4. 结束（实心圆）

#### 泳道 2：后端服务（中间）
- **节点序列**：
 1. 开始（实心圆）
 2. [用户首次登录，调用 ensure_default_groups(uid)]（矩形）
 3. [查询用户角色和课程列表]（矩形）
 4. {有课程？}（菱形判断）
    - N → 结束
    - Y → 步骤 5
 5. [遍历课程列表]（矩形）
 6. {该课程的聊天室是否已存在？}（菱形判断，按 chat_lesson_{lesson_id} 查询 groups_chat）
    - Y → 步骤 7（跳过创建）
    - N → [创建聊天室（groups_chat.creator='system'）]（矩形）
 7. [将当前用户加入聊天室（group_members）]（矩形）
 8. [关联聊天室到课程群组（user_group_chats）]（矩形）
 9. {还有下一门课程？}（菱形判断）
    - Y → 回到步骤 5
    - N → 步骤 10
 10. commit
 11. 结束（实心圆）

### 流程二：聊天室成员添加（创建 + 邀请合并）

#### 泳道 1：操作者（前端）
- **节点序列**：
 1. 开始（实心圆）
 2. [填写名称、选择分类、勾选初始成员，点击创建聊天室]（矩形，调用 POST /api/groups）
 3. [或在聊天室详情中点击"+ 邀请"，勾选用户，发送邀请]（矩形，调用 POST /api/groups/{id}/invite）
 4. 结束（实心圆）

#### 泳道 2：后端服务（中间）
- **节点序列**（创建分支）：
 1. {名称和成员非空？}→ N → 400
 2. [生成 group_id，验证成员 UID 有效性]（矩形）
 3. [向 groups_chat 插入聊天室，向 group_members 插入创建者和已选成员（创建者 role='admin'）]（矩形）
 4. [向 group_messages 插入"聊天室已创建"]（矩形）
 5. commit

- **节点序列**（邀请分支）：
 1. [遍历待邀请成员列表]（矩形）
 2. {用户存在且尚未加入？}（菱形判断）
    - N → 跳过
    - Y → 步骤 3
 3. [向 notifications 插入 chat_invite 通知（status='pending'，extra 含 chat_id/chat_name）]（矩形）
 4. {还有下一个？}→ Y → 回到步骤 2
 5. commit

#### 泳道 3：被邀请者（前端/通知中心）
- **节点序列**：
 1. [通知中心轮询到 chat_invite 通知]（矩形）
 2. [显示邀请卡片，含聊天室名称、"同意"/"拒绝"按钮]（矩形）
 3. {用户点击？}（菱形判断）
    - 同意 → 调用 POST /api/notifications/{id}/approve
    - 拒绝 → 调用 POST /api/notifications/{id}/reject → 结束
 4. [后端处理：向 group_members 插入新成员，向 group_messages 插入"xxx 接受了邀请"]（矩形）
 5. [通知卡片变为"已处理"]（矩形）
 6. 结束（实心圆）

### 流程三：群主管理操作（含解散聊天室）

#### 3.1 解散聊天室

#### 泳道 1：群主（前端）
- **节点序列**：
 1. [在聊天室详情中点击"解散聊天室"]（矩形）
 2. {确认解散？}（菱形判断）
    - N → 结束
    - Y → 步骤 3
 3. 调用 `POST /api/groups/{id}/dissolve`
 4. 结束（实心圆）

#### 泳道 2：后端服务
- **节点序列**：
 1. {当前用户 role='admin'？}→ N → 403
 2. [查询聊天室名称和所有成员 UID]（矩形）
 3. [删除 group_members，插入解散系统消息]（矩形）
 4. [遍历成员列表，向 notifications 插入解散通知]（矩形，type='system'，content='聊天室「{name}」已解散'）
 5. [删除 groups_chat、user_group_chats 记录]（矩形）
 6. commit

#### 3.2 踢出成员

#### 泳道 1：群主（前端）
1. 开始（实心圆）
2. [在成员列表中点击"踢出"]（矩形）
3. {确认？}→ N → 结束
4. 调用 `POST /api/groups/{id}/kick`
5. 结束（实心圆）

#### 泳道 2：后端服务
1. {当前用户 role='admin'？}→ N → 403
2. {目标不是 admin？}→ N → 400
3. [删除该用户的消息和成员记录，插入系统消息"{name} 已被移出"]（矩形）
4. {剩余成员数 ≤ 1？}→ Y → [自动解散聊天室（含通知发送）]
5. commit

#### 3.3 设置/取消管理员 & 发布公告

#### 泳道 1：群主/管理员（前端）
1. [点击"设为管理"或"取消管理"或"发布公告"]（矩形）
2. 调用对应 API（POST /api/groups/{id}/admin 或 /announcement）
3. 结束（实心圆）

#### 泳道 2：后端服务
1. {当前用户 role='admin'？}（菱形判断）
    - N → 403
    - Y → 步骤 2
2. [更新 group_members.role 或向 group_messages 插入公告]（矩形）
3. commit

### 流程四：退出聊天室

#### 泳道 1：用户（前端）
1. 开始（实心圆）
2. [在聊天室详情中点击"退出聊天室"]（矩形）
3. {确认？}→ N → 结束
4. 调用 `POST /api/groups/{id}/leave`
5. 结束（实心圆）

#### 泳道 2：后端服务
1. {用户在聊天室中？}→ N → 403
2. {groups_chat.creator='system'？}→ Y → 403"课程/班级群无法退出！"
3. {role='admin' 且成员数 > 1？}→ Y → 403"群主不能退出，请转让群主"
4. [插入系统消息，从 group_members 删除用户]（矩形）
5. commit
6. {剩余成员数 ≤ 1？}→ Y → [自动解散（含通知发送）]

## 3. 跨泳道连接线说明
- 泳道 3 [教务平台] → 向左 → 泳道 2 [查询课程数据]
- 泳道 1 [创建/邀请操作] → 向右 → 泳道 2 [处理请求]
- 泳道 2 [插入通知] → 向右 → 泳道 3 [被邀请者收到通知]
- 泳道 3 [同意/拒绝] → 向左 → 泳道 2 [处理审批]
- 泳道 1 [群主管理操作] → 向右 → 泳道 2 [执行管理逻辑]
