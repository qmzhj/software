# 流程图编写要求

## 参考样例

以 [`描述示例.md`](./描述示例.md) 中的格式为模板，编写以下功能模块的流程图描述。

## 通用格式规范

每个流程图描述文件遵循以下结构：

1. **图表类型**：UML 活动图 / 泳道图
2. **布局说明**：泳道数量（单泳道/多泳道）、排列方向、命名
3. **起止节点**：实心圆（开始/结束）
4. **泳道详情**：每个泳道内的节点序列（矩形=动作、菱形=判断、圆角矩形=起止），标注 Y/N 分支
5. **跨泳道连接线**（仅多泳道）：说明数据/请求在泳道间的传递

## 模块划分与输出

| # | 模块 | 重点关注 | 输出文件 |
|---|------|----------|----------|
| 1 | **群组** | 系统群组的自动创建逻辑；系统群组不可修改/不可删除的约束 | `群组流程描述.md` |
| 2 | **聊天室** | 聊天室的创建（含邀请发送逻辑）、解散（含通知发送逻辑）、群主对聊天室的管理（踢人/设管理/公告） | `聊天室流程描述.md` |
| 3 | **即时消息** | 私聊与群聊的发送、接收（SSE 推送）、消息撤回 | `消息流程描述.md` |
| 4 | **成员关系** | 好友添加/删除、黑名单、好友申请的通知与审批 | `成员关系流程描述.md` |
| 5 | **通话与权限** | 通话邀请发起与接收、私聊通话权限（call_preferences）、群聊通话权限（group_members.call_notify） | `通话与权限流程描述.md` |
| 6 | **系统通知** | 不绘制流程图。系统通知本质是其他模块的副产品（解散/踢出/好友申请等触发写入），逻辑已分散在各模块流程中，无独立编排价值 | 无 |

## 注意事项

- 前 5 个模块均为多角色交互，使用**泳道图**描述。泳道划分参考：用户（前端）→ 后端API → 数据库 →（如有）第三方
- 重点体现**判断分支**（权限检查、条件校验）和**异常路径**（失败/拒绝/超时）
- 每个文件独立成文，遵循 `描述示例.md` 的 Markdown 格式层次
