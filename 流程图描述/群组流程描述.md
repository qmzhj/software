# UML 活动图：群组流程（泳道图）

## 1. 图表结构
- **类型**：UML 活动图（Activity Diagram）/ 泳道图
- **布局**：横向 3 泳道，从左到右依次排列
- **泳道标题栏颜色**：
  - 学校教务平台：红色
  - 后端服务：黄色
  - 用户（前端）：蓝色
- **起止节点**：顶部实心黑圆（开始），底部实心黑圆（结束）

## 2. 泳道详情与流程

### 流程一：系统群组自动创建（用户首次登录时触发）

#### 泳道 1：学校教务平台（左侧）
- **节点序列**：
 1. 开始（实心圆）
 2. [提供学生录取名单、课程选课结果等数据]（矩形）
 3. [每日凌晨 00:00-01:00 通过 API 同步至系统]（矩形）
 4. 结束（实心圆）

#### 泳道 2：后端服务（中间）
- **节点序列**：
 1. 开始（实心圆）
 2. [接收用户首次登录成功事件]（矩形）
 3. [调用 ensure_default_groups(uid)]（矩形）
 4. [查询 user_group_members 是否已有系统群组]（矩形）
 5. {是否已有系统群组？}（菱形判断）
    - Y → 结束
    - N → 步骤 6
 6. [创建"即时聊天"群组]（矩形，向 user_groups 写入 group_type='system', category='即时聊天'，向 user_group_members 写入成员）
 7. [创建"私聊"群组]（矩形，向 user_groups 写入 group_type='system', category='私聊'，向 user_group_members 写入成员）
 8. [查询用户角色，获取课程列表]（矩形）
    - student：从 lesson_stu 查出所选课程
    - teacher：从 lesson 查出所授课程
 9. {有课程数据？}（菱形判断）
    - N → commit，结束
    - Y → 步骤 10
 10. [创建"课程"群组]（矩形，同一课程的学生/教师共享课程聊天室）
 11. [遍历课程列表，为每门课自动创建聊天室]（矩形，groups_chat.creator='system'，group_members 加入当前用户）
 12. [关联聊天室到课程群组]（矩形，向 user_group_chats 插入记录）
 13. commit
 14. 结束（实心圆）

### 流程二：用户创建/删除自定义群组

#### 泳道 1：用户（前端）
- **节点序列**：
 1. 开始（实心圆）
 2. [输入群组名称、勾选成员和聊天室，点击创建]（矩形，调用 POST /api/user-groups）
 3. [在群组列表多选模式下勾选自定义群组，点击删除]（矩形，系统群组置灰不可选，调用 POST /api/user-groups/batch-delete）
 4. 结束（实心圆）

#### 泳道 2：后端服务（中间）
- **节点序列**（创建）：
 1. {名称非空？}→ N → 400
 2. [向 user_groups、user_group_members、user_group_chats 插入数据]（矩形）
 3. commit，返回 201

- **节点序列**（删除）：
 1. [遍历 group_ids，校验 creator 和 group_type]（矩形）
 2. {创建者是当前用户且为自定义群组？}（菱形判断）
    - Y → [删除 user_groups、user_group_members、user_group_chats 记录]（矩形）
    - N → 跳过
 3. commit，返回已删除数量

## 3. 跨泳道连接线说明
- 泳道 1 [同步数据] → 向右 → 泳道 2 [接收登录事件后查询课程]
- 泳道 2 [创建群组/聊天室] → 向左 → 泳道 3 [群组列表展示]
- 泳道 3 [创建/删除请求] → 向右 → 泳道 2 [处理请求]
