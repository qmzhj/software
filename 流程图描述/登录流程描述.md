# UML 活动图：用户登录流程（泳道图）

## 1. 图表结构
- **类型**：UML 活动图（Activity Diagram）/ 泳道图
- **布局**：横向 3 泳道，从左到右依次排列
- **泳道标题栏颜色**：
  - 用户登录页面：蓝色
  - 用户认证服务：黄色
  - 用户数据服务：绿色
- **起止节点**：顶部实心黑圆（开始），底部实心黑圆（结束）

## 2. 泳道详情与流程

### 泳道 1：用户登录页面（左侧）
- **节点序列**：
  1. 开始（实心圆）
  2. [输入学工号]（矩形）
  3. [输入密码]（矩形）
  4. [点击登录]（矩形）
  5. [发送登录请求]（矩形，POST /api/login）
  6. {登录成功？}（菱形判断，接收来自泳道 2 的返回结果）
     - Y → 步骤 7
     - N → 步骤 8
  7. [保存 Token，跳转主页面]（矩形）
  8. [显示错误信息]（矩形）
  9. 结束（实心圆）

### 泳道 2：用户认证服务（黄色栏）
- **节点序列**：
  1. 接收登录请求 → [查询用户]（矩形）
     - 输出：→ 泳道 3 的 [查询用户数据]
     - 返回：接收泳道 3 返回的用户数据
  2. {账号存在？}（菱形判断）
     - N → 返回泳道 1 的 步骤 6（标注"返回 400：账号不存在"）
     - Y → 步骤 3
  3. {账户已锁定？}（菱形判断，检查 locked 字段）
     - Y → 步骤 4
     - N → 步骤 5
  4. {锁定时间已过？}（菱形判断，比较当前时间与 unlock_time）
     - Y → [解除锁定]（矩形，UPDATE locked=0, login_fails=0）
       - 执行后进入步骤 5
     - N → 返回泳道 1 的 步骤 6（标注"返回 403：账户已锁定，请30分钟后重试"）
  5. [验证密码]（矩形，SHA256 哈希比对）
     - 调用 hash_password 计算输入密码哈希
     - 与数据库存储的哈希值比对
  6. {密码正确？}（菱形判断）
     - N → 步骤 7
     - Y → 步骤 9
  7. [累加登录失败次数]（矩形，login_fails += 1）
  8. {失败次数达到 5 次？}（菱形判断）
     - Y → [锁定账户]（矩形，SET locked=1, unlock_time=now+1800s）
       - 返回泳道 1 的 步骤 6（标注"返回 403：账户已锁定，请30分钟后重试"）
     - N → 返回泳道 1 的 步骤 6（标注"返回 400：密码错误"）
  9. [生成 Token]（矩形，secrets.token_hex(16) 生成 32 位十六进制字符串）
  10. [存储 Token 并重置失败次数]（矩形，存入全局 tokens 字典，SET login_fails=0）
  11. 返回泳道 1 的 步骤 6（标注"返回 200：{token, uid, name, role}"）

### 泳道 3：用户数据服务（绿色栏）
- **节点序列**：
  1. [查询用户数据]（矩形，SELECT * FROM users WHERE uid=?）
     - 返回用户数据行（含 uid, name, password, role, locked, login_fails, unlock_time, registed）
     - 输出至泳道 2
  2. [更新登录失败次数]（矩形，UPDATE users SET login_fails=? WHERE uid=?）
     - 输出至泳道 2
  3. [锁定账户]（矩形，UPDATE users SET locked=1, unlock_time=? WHERE uid=?）
     - 输出至泳道 2
  4. [解除锁定]（矩形，UPDATE users SET locked=0, login_fails=0 WHERE uid=?）
     - 输出至泳道 2
  5. [重置失败次数]（矩形，UPDATE users SET login_fails=0 WHERE uid=?）
     - 输出至泳道 2

## 3. 跨泳道连接线说明
- 泳道 1 [发送登录请求] → 向右 → 泳道 2 [查询用户]
- 泳道 2 [查询用户] → 向右 → 泳道 3 [查询用户数据]
- 泳道 3 [查询用户数据] → 向左 → 泳道 2 {账号存在？}
- 泳道 2 {账号不存在} → 向左 → 泳道 1 {登录成功？}（标注：400 账号不存在）
- 泳道 2 {锁定时间未过} → 向左 → 泳道 1 {登录成功？}（标注：403 账户已锁定）
- 泳道 2 [解除锁定]（泳道 3 数据操作后）→ 进入泳道 2 [验证密码]
- 泳道 2 [累加失败次数] → 向右 → 泳道 3 [更新登录失败次数]
- 泳道 2 {失败达到 5 次} → 向右 → 泳道 3 [锁定账户]（标注：SET unlock_time=now+1800s）
- 泳道 2 {密码错误} → 向左 → 泳道 1 {登录成功？}（标注：400 密码错误）
- 泳道 2 {锁定} → 向左 → 泳道 1 {登录成功？}（标注：403 已锁定）
- 泳道 2 [重置失败次数] → 向右 → 泳道 3 [重置失败次数]
- 泳道 2 [生成 Token] → 向左 → 泳道 1 {登录成功？}（标注：200 {token, uid, name, role}）
