# UML 活动图：赛事组队流程（泳道图）

## 1. 图表结构
- **类型**：UML 活动图（Activity Diagram）/ 泳道图
- **布局**：横向 3 泳道
- **泳道标题栏颜色**：
  - 用户（前端）：蓝色
  - 赛事组队服务：黄色
  - 组长/审批人（通知中心）：绿色
- **起止节点**：顶部实心黑圆（开始），底部实心黑圆（结束）

## 2. 泳道详情与流程

### 流程一：创建小组

#### 泳道 1：用户（左侧）
- **节点序列**：
 1. 开始（实心圆）
 2. [填写组名、人数上限、简介]（矩形）
 3. [确认创建]（矩形）
 4. 结束（实心圆）

#### 泳道 2：赛事组队服务（中间）
- **节点序列**：
 1. [创建小组，将创建者设为组长]（矩形）
 2. 结束（实心圆）

### 流程二：参与小组（申请加入与退出）

#### 泳道 1：用户（左侧）
- **节点序列**：
 1. 开始（实心圆）
 2. [查看赛事下的小组列表]（矩形）
 3. {判断用户状态}（菱形判断）
    - 该小组为组长 → [显示"设置满员/招募中"按钮]
    - 该小组为成员（非组长）→ [显示"退出小组"按钮]
    - 已在其他小组 → [提示"你已在其他小组"，无操作按钮]
    - 未加入且小组已满员 → [显示灰色"已满员"文字，无按钮]
    - 未加入且小组招募中 → 步骤 4
 4. [点击"申请加入"]（矩形）
 5. [等待组长审批]（矩形）
 6. {审批结果}（菱形判断）
    - 同意 → [成为小组成员]
    - 拒绝 → [显示申请被拒绝]
 7. 结束（实心圆）

#### 泳道 2：赛事组队服务（中间）
- **节点序列**：
 1. 接收申请
 2. {小组已满员？}（菱形判断）
    - Y → 返回"该小组已满员"
    - N → 步骤 3
 3. [向组长发送审批通知]（矩形）
 4. {组长审批}（菱形判断）
    - 同意 → [将申请人加入小组]
    - 拒绝 → [通知申请人被拒绝]
 5. 或：[收到退出请求，校验身份后移除成员]（矩形）
 6. 结束（实心圆）

#### 泳道 3：组长（右侧）
- **节点序列**：
 1. [收到加入申请通知]（矩形）
 2. [同意或拒绝申请]（矩形）
 3. 或：[设置小组为满员/招募中状态]（矩形）
 4. 结束（实心圆）
