# UML 活动图：忘记密码流程（泳道图）

## 1. 图表结构
- **类型**：UML 活动图（Activity Diagram）/ 泳道图
- **布局**：横向 3 泳道，从左到右依次排列
- **泳道标题栏颜色**：
  - 用户登录页面：蓝色
  - 用户认证服务：黄色
  - 用户数据服务：绿色
- **起止节点**：顶部实心黑圆（开始），底部实心黑圆（结束）

## 2. 泳道详情与流程

### 泳道 1：用户登录页面（左侧）
- **节点序列**：
  1. 开始（实心圆）
  2. [点击"忘记密码？"]（矩形）
  3. [输入学工号]（矩形）
  4. [输入手机号]（矩形）
  5. {手机号格式正确？}（菱形判断，前端校验 11 位数字且以 1 开头）
     - N → [显示手机号格式错误提示]（矩形）
       - 返回步骤 4（向上箭头）
     - Y → 步骤 6
  6. [发送验证码]（矩形，调用 sendSmsCode() 发送 POST /api/change_password）
  7. {发送成功？}（菱形判断，接收泳道 2 返回结果）
     - N → [显示错误信息]（矩形）
       - 返回步骤 4（向上箭头）
     - Y → 步骤 8
  8. [60 秒倒计时，按钮禁用]（矩形）
  9. [输入短信验证码]（矩形）
  10. [输入新密码]（矩形）
  11. [确认新密码]（矩形）
  12. {两次密码一致？}（菱形判断，前端校验）
      - N → [显示密码不一致提示]（矩形）
        - 返回步骤 10（向上箭头）
      - Y → 步骤 13
  13. {密码格式正确？}（菱形判断，前端校验长度至少 8 位）
      - N → [显示密码格式错误提示]（矩形）
        - 返回步骤 10（向上箭头）
      - Y → 步骤 14
  14. [提交重置密码请求]（矩形，调用 resetPassword() 发送 POST /api/change_password）
  15. {重置成功？}（菱形判断，接收泳道 2 返回结果）
      - Y → 步骤 16
      - N → 步骤 17
  16. [显示"密码修改成功，请返回登录"并在 3 秒后自动跳转回登录页]（矩形）
  17. [显示错误信息]（矩形）
  18. 结束（实心圆）

### 泳道 2：用户认证服务（黄色栏）
- **节点序列**：
  1. 接收请求 → {操作类型？}（菱形判断，根据 action 字段区分）
     - send_code → 步骤 2
     - reset_password → 步骤 9
     - 其他 → 返回泳道 1 的步骤 7（标注"返回 400：无效的操作类型"）

  **发送验证码分支（send_code）：**
  2. [查询用户数据]（矩形）
     - 输出：→ 泳道 3 的 [查询用户数据]
     - 返回：接收泳道 3 返回的用户数据
  3. {账号存在？}（菱形判断）
     - N → 返回泳道 1 的步骤 7（标注"返回 404：该账号不存在"）
     - Y → 步骤 4
  4. {手机号匹配？}（菱形判断，比对录入手机号与数据库 phone 字段）
     - N → 返回泳道 1 的步骤 7（标注"返回 404：学号/工号与手机号不匹配"）
     - Y → 步骤 5
  5. [生成验证码]（矩形，开发阶段固定为 "123456"）
  6. [调用短信发送接口]（矩形，send_sms(phone, code)，当前为模拟调用）
  7. {短信发送成功？}（菱形判断）
     - N → 返回泳道 1 的步骤 7（标注"返回 500：短信发送失败"）
     - Y → 步骤 8
  8. [存储验证码]（矩形，存入 verification_codes 字典，有效期 5 分钟，含尝试次数记录）
     - 返回泳道 1 的步骤 7（标注"返回 200：验证码已发送"）

  **重置密码分支（reset_password）：**
  9. {参数完整？}（菱形判断，校验 phone、code、new_password 均不为空）
     - N → 返回泳道 1 的步骤 15（标注"返回 400：请填写完整信息"）
     - Y → 步骤 10
  10. {密码格式合法？}（菱形判断，正则校验密码复杂度）
      - N → 返回泳道 1 的步骤 15（标注"返回 400：密码需包含大小写字母和数字，至少8位"）
      - Y → 步骤 11
  11. {验证码有效？}（菱形判断，检查验证码是否存在且未过期）
      - N → 返回泳道 1 的步骤 15（标注"返回 400：验证码已过期，请重新获取"）
      - Y → 步骤 12
  12. {验证码正确？}（菱形判断，比对用户输入验证码与存储的验证码）
      - N → [累加错误次数]（矩形）
        - {错误次数 >= 5？}（菱形判断）
          - Y → [清除验证码]（矩形）
            - 返回泳道 1 的步骤 15（标注"返回 400：验证失败次数过多，请重新获取"）
          - N → 返回泳道 1 的步骤 15（标注"返回 400：验证码不正确"）
      - Y → 步骤 13
  13. [查询用户数据]（矩形）
      - 输出：→ 泳道 3 的 [查询用户数据]
      - 返回：接收泳道 3 返回的用户数据
  14. {手机号匹配？}（菱形判断，二次确认 uid 与 phone 的对应关系）
      - N → 返回泳道 1 的步骤 15（标注"返回 404：学号/工号与手机号不匹配"）
      - Y → 步骤 15
  15. [密码加密]（矩形，SHA256(new_password + "CampusFakeSalt2024!")）
  16. [更新密码并清除验证码]（矩形）
      - 输出：→ 泳道 3 的 [更新密码]
  17. 返回泳道 1 的步骤 15（标注"返回 200：密码修改成功"）

### 泳道 3：用户数据服务（绿色栏）
- **节点序列**：
  1. [查询用户数据]（矩形，SELECT * FROM users WHERE uid=?）
     - 返回用户数据行（含 uid, name, phone, password 等字段）
     - 输出至泳道 2
  2. [更新密码]（矩形，UPDATE users SET password=? WHERE uid=?）
     - 输出至泳道 2

## 3. 跨泳道连接线说明
- 泳道 1 [发送验证码] → 向右 → 泳道 2 {操作类型？}
- 泳道 2 [查询用户数据] → 向右 → 泳道 3 [查询用户数据]
- 泳道 3 [查询用户数据] → 向左 → 泳道 2 {账号存在？} / {手机号匹配？}
- 泳道 2 {验证码正确} → 进入泳道 2 [查询用户数据]（重置密码分支）
- 泳道 2 {验证码正确后的手机号匹配} → 向右 → 泳道 3 [查询用户数据]（二次确认）
- 泳道 2 [更新密码并清除验证码] → 向右 → 泳道 3 [更新密码]
- 泳道 3 [更新密码] → 向左 → 泳道 2 返回路径
- 泳道 2 各失败返回 → 向左 → 泳道 1 对应的 {发送成功？} 或 {重置成功？} 判断节点（标注对应状态码与错误信息）
